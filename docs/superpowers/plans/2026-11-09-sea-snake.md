# Sea Snake (Kraken Phase 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the Sea Snake: a free-swimming, organic, jointed-physics enemy with a PPO-trained chase brain (scripted fallback), killable by shots, damaging the player on contact, built so its root end can later be anchored as a Kraken tentacle.

**Architecture:** Mirrors the Inchworm exactly: `physics/sea_snake.py` (private Pymunk space, spring-torque muscles, anisotropic water drag for propulsion) → `creatures/traits/sea_snake.py` (owns physics, picks neural vs scripted command, exports pose snapshot) → `entities/sea_snake.py` Body (draws, exposes `collision_segments`). Contact damage is a separate trait (`stingsShip`) that tests every segment against the ship. Neural wiring copies the Inchworm's adapter/task/driver pattern.

**Tech Stack:** Python, pygame, Pymunk, NumPy policy (`learning/policy.py`), PPO via `tools/ppo_neural` / `learning/run.py`, pytest.

**Spec:** `docs/superpowers/specs/2026-11-09-kraken-boss-design.md` (Phase 1 only; Phase 2 gets its own plan after the snake is trained).

## Global Constraints

- Creature = Body + Traits; Body draws and never decides; one trait per behaviour, transferable (`ARCHITECTURE.md`, memory).
- Cost budget: one snake ≈ Inchworm-class, about 0.6 ms/frame (4 tentacles ≈ 2.4 ms later).
- Solver blow-up guard: raise `RuntimeError` from `step`; the trait rebuilds physics, counts `snake_resets`, and calls `enc.kill(c)` after more than 3 resets.
- Pymunk objects excluded from deepcopy via `Trait.LIVE`.
- Scripted fallback when no weights; `tests/conftest.py` sets `SEA_SNAKE_POLICY=""` like `INCHWORM_POLICY`.
- Tests cover behaviour, not internals; few and valuable. No compat shims for old runs/recordings.
- Root end must support `pin_root(point)` and `release_root()` (needed by Phase 2).
- Do not add the snake to the wallcrawler/inchworm wall-planting special case in `game_handlers/spawn_manager.py:261-266`.
- Starting or restarting a training run: ask the user first, and `git pull` from main (merging it into the working branch) before the run starts.

## Review Focus

- Snake spawned inside/against a wall: physics must not explode or tunnel out of the maze (test with a wall touching the head).
- Target absent (ship dead/respawning): snake idles/drifts without errors or NaN.
- Two ships (multiplayer): chases the nearest living ship; `stingsShip` checks each ship, and shielded ships take no damage.
- Contact damage is rate-limited, not charged every frame while overlapping.
- Death: portrait deepcopy works and a dying snake does not crash on a blown solver.
- Shots hit any link and miss empty space inside the bounding area.

- [ ] **Step 3: Implement** `physics/sea_snake.py` modelled on `physics/inchworm.py`: private `pymunk.Space` (iterations 30, damping near 1), `LINKS` capsule bodies (`Segment` skin = 0.3×radius, collision_type 1), `PivotJoint` + `RotaryLimitJoint(±MAX_BEND)` between neighbours, muscles as manual spring torques toward `muscle × MAX_BEND`, walls mirrored via a `_sync_surfaces` equivalent (collision_type 2).
